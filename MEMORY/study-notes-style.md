# 学习笔记分析方法（按需加载）

> 本文件从 `AGENTS.md` 拆出，仅在做学习笔记 / 架构分析 / 系统梳理时按需读取。

**类型**：Feedback

用户要求写学习笔记时，自动采用下述分析方法论（基于"血量系统架构分析"的质量标准）：

**为什么**：用户对"血量系统架构分析"笔记满意，认可这种分析深度和组织方式。这是已确认有效的风格。

**如何应用**：当用户要求写学习笔记、梳理架构、分析系统时，按照以下模板和方法执行：

## 分析流程

1. **通读所有相关文件** — 不要只看一个文件，要追踪完整的调用链和数据流
2. **识别系统的边界** — 这个系统涉及哪些类？各自扮演什么角色？
3. **画数据流图** — 用 ASCII art 画出完整的传递链路（服务器端和客户端分别画）
4. **逐层拆解每个类的职责** — 不只说"是什么"，还要说"为什么这样设计"
5. **找出设计亮点和潜在问题** — 分析为什么这样做是好的，或者哪里有坑
6. **用表格做总结** — 把类、角色、职责汇总到一张表里

## 笔记结构模板

```
# XX系统架构分析

## 一、整体概览：X大系统协同工作
    — 用 ASCII 框图展示整体关系
   — 一屏看清全貌

## 二、逐系统分析
   每个子系统按以下结构：
   2.1 类层次（继承关系）
   2.2 传递链路（ASCII 流程图，服务器+客户端双路径）
   2.3 关键设计决策（为什么这样做而不是那样做）

## 三、完整数据流（一次完整交互的时间线）
   — 服务器 + 客户端多列的 ASCII 时间线

## 四、各类角色总结（表格）

## 五、设计亮点 / 待改进点
```

## 质量控制

- 必须画至少一张 ASCII 流程图
- 必须区分服务器端和客户端两条执行路径
- 必须有一张类角色总结表
- 必须解释"为什么这样设计"而不是仅描述"代码做了什么"
- 中文书写，简洁不啰嗦
